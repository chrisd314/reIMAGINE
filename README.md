# Once Upon a World

**Do folktales form communities around where they were recorded, or around the kind of story they tell?**

This is a reproducible analysis of 1,498 recorded folktales (the *Annotated Folktales* corpus, from D. L. Ashliman's *Folktexts*), with a static, interactive research website for exploring it. It is a DTU 02805 *Social Graphs and Interactions* course project.

Operationally, it asks whether communities in a text-similarity network align more closely with *recorded* geographical provenance or with ATU *tale types*, and whether the answer differs between lexical (TF–IDF) and semantic (sentence-embedding) representations.

> This repository holds the analysis and the website, not the academic report. Read the claim boundaries in LIMITATIONS.md before quoting any number.

## Quick start (Windows, macOS or Linux)

Requirements: [uv](https://docs.astral.sh/uv/) with Python 3.11, and Node.js ≥ 20.19 (Node 24 LTS was used). About 2 GB free disk for the model and PyTorch.

```bash
# 1. Python environment (versions pinned in uv.lock)
uv sync

# 2. Full pipeline: fetch -> clean -> audit -> cohorts -> TF-IDF -> embeddings -> graphs
#    -> modularity null -> distance -> validation sample -> layouts -> web export
uv run python -m analysis all
#    Re-runs skip stages whose inputs (config section + content hashes of upstream files)
#    are unchanged; add --force to rerun.
#    Run single stages by name, e.g.: uv run python -m analysis analyze export

# 3. Tests on the code and on the produced outputs, then the headline numbers of this run
uv run pytest
uv run python scripts/summarise_run.py

# 4. Website
cd web
npm ci
npm run dev        # development server: http://localhost:5173/
npm run build      # type-check + production build into web/dist
npm run preview    # serve the production build: http://localhost:4173/
```

If Node is not installed system-wide, a portable Node 24 LTS (checksum-verified) can be placed in `.tools/`. This was done on the development machine; `.tools/` is git-ignored. On Windows: `$env:PATH = "$PWD\.tools\node-v24.22.2-win-x64;$env:PATH"`.

Browser checks (with a server running): `uv run python tests/browser/journey.py http://localhost:4173/ outputs/browser/journey-desktop`, plus `--mobile`, `--keyboard`, `--reduced`.

Typical timings on a laptop CPU: embedding about 5 minutes on the first run (cached afterwards), graphs and label shuffles about 4 minutes, modularity null a few minutes, layouts about 5 minutes.

## What the pipeline does

| Stage | Module | Main outputs |
| --- | --- | --- |
| fetch | `analysis/fetch.py` | `data/raw/` (immutable) + `data/raw/source_manifest.json` (URL, commit, SHA-256, licence, role) |
| clean | `analysis/clean.py` | `data/interim/records.parquet`, `outputs/audit/cleaning_log.csv` |
| audit | `analysis/audit.py` | `outputs/audit/raw_audit.json` (reproduces every diagnostic in the brief) |
| cohorts | `analysis/cohorts.py` | `data/processed/narratives.parquet`, `cohorts.csv`, `outputs/audit/inclusion_ledger.csv` |
| lexical | `analysis/lexical.py` | one TF–IDF space (negation kept) + name-masked variant |
| semantic | `analysis/semantic.py` | MiniLM chunk and tale vectors (≤ 200-token chunks, cached by content hash) |
| analyze | `analysis/analyze.py` | graphs at 5/10/15%, Louvain (seeds 42/7/19), NMI, assortativity and neighbour checks with 1,000 label shuffles |
| modnull | `analysis/modnull.py` | degree-preserving null for modularity |
| distance | `analysis/distance.py` | haversine distance vs similarity, whole-location shuffles |
| validation | `analysis/validation.py` | blind stratified review sample; summary stays *pending* until annotations exist |
| layouts | `analysis/layouts.py` | display-only layouts (ForceAtlas2 of a backbone) and PCA |
| export | `analysis/export.py` | `web/public/data/` (one `run_id` stamped on every payload) |

Settings live in `config.yaml`. They were frozen before any agreement statistic was computed; later changes are logged in ANALYSIS_PLAN.md.

## Layout

```text
analysis/            pipeline (python -m analysis ...)
config.yaml          all settings (frozen; changes logged in ANALYSIS_PLAN.md)
data/raw/            pinned downloads + manifest (immutable)
data/mappings/       provenance_map.csv (reviewable), text_review.csv (cleaning decisions)
data/interim/, data/processed/   derived data (large arrays git-ignored; reproducible)
outputs/audit|metrics|validation|figures|browser/   machine-readable results and checks
scripts/             draft_provenance_map.py (generated the first mapping draft)
tests/               metric-equivalence and pipeline-output tests; tests/browser/ journeys
web/                 React + TypeScript + Vite site; web/public/data is generated by export
```

## Validation

The Validation page is a blind annotation tool. Export its CSVs to `outputs/validation/annotations/`, then run `uv run python -m analysis validation export`. Agreement is reported as raw agreement with disagreement counts. Until then the status is **pending**.
